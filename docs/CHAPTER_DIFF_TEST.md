# 章を行き来したときの DOM 残り検査（設計案・2026-08-08）

第1章セッションからの依頼。**実装は第2章が持ち、第1章としての正解の判定は第1章が持つ。**
まだ書いていない。この設計に意見をもらってから作る。

---

## 何を捕まえるものか

`applyChapter()` は画面を読み込み直さない。だから
**第2章で遊ぶ → 保存してもどる → 第1章** が通常操作でできてしまい、
第2章が書き換えた DOM が第1章の画面に残る。

今日はこの型を3件踏んだ。壊れ方が毎回違う。

| 件 | 残ったもの | 種類 |
|---|---|---|
| §36 `syncAreaBar` | 外観・集客・増築のパネル | **class（hidden）** |
| §37 `renderKouko` | 「🏦 横浜信用金庫（融資課）／枠5000万円」 | **innerHTML** |
| §37 融資タブ | 資金繰りの中身3つの居場所 | **要素の親（並び）** |

共有側のフックは130か所超、第2章だけの `CONF` キーは70近く。目視で追う規模ではない。

## 測り方

```
① guardBoot(1)               → 記録A（これが正）
② applyChapter(2) → guardBoot(2) → 画面という画面をひととおり開く
③ applyChapter(1) → guardBoot(1) → 記録B
④ A と B を機械的に比べる
```

### なぜ両端で `guardBoot(1)` するか

**遊べば当然変わるもの（手持ち資金・日数・評判）を、そもそも差分に出さないため。**
両端で同じ初期状態を作り直せば、**残った差分はDOMの残りかすだけ**になる。
「差分を全部バグ扱いしない」という指摘への答えを、除外リストではなく手順で作る。

> ⚠ それでも消えない揺れがある（バイトの候補・天気などの乱数）。
> **2回続けて走らせて、①と③を入れ替えても出る差分だけを本物として扱う。**
> 揺れる id は結果に「不安定」と印を付けて出す。

### 記録するもの

id を持つ要素を全部たどり、要素ごとに

- `class`（`hidden` はここに出る）
- `hidden` 属性 と `getComputedStyle().display`
- `style.cssText`
- `innerHTML`（長いものはハッシュ＋先頭120字）
- **親要素の id と、その中での位置**（融資タブの引っ越しはここでしか捕まらない）

`textContent` だけでは足りない。今日の3件がそれぞれ別の欄で壊れている。

### 開いた画面を数える

**開き忘れがそのまま検査漏れになる。**
開く画面は表で持ち、結果に「開いた画面／開けなかった画面」を必ず並べて出す。

資金繰り・運営（料金／ルール／バイト／融資）・バイト管理・面接・カタログ（全タブ×全階）・
館内案内図・外観・集客・増築・データ・日報・お出かけ・朝の選択・設置バー・客の札 …

`.overlay` と `.modal` を index.html から自動で列挙し、
**表に載っていない画面が見つかったら、それも結果に出す**（表の抜けに気づけるように）。

## 出すもの

直す前に、まず一覧をそのまま第1章へ送る。

```
[要素の id] どの欄が違うか
  A: …（第1章の正）
  B: …（第2章のあと）
  判定: 未定
```

**第2章側で直すもの／第1章の文言として確定させるもの、の切り分けは第1章が決める。**
こちらでバグと決めつけない。

## 置き場所と走らせ方

`js/dev/chapterDiff.js`。`chapterGuard.js` と同じく **localhost かつポート指定ありのときだけ**読み込む。
配信ビルド（`tools/build-web.js` → `www/`）には `js/dev/` も `js/ch2b/` も入らないので、
**このテストが直す不具合は、配信中の第1章には出ない。**

```js
await chapDiff();        // 一覧を返す
await chapDiff({ twice: true });   // 2回走らせて、揺れる id に印を付ける
```
