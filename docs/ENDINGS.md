| 5 | 人気店 | それ以外の敗北すべて | 勝てなかったが、店は続いていく |

**廃業の3条件**（どれか1つで成立）
1. `G.ch2.billMissed` … 月の支払いを一度でも落とした（信金の門が閉じる印。数字の傷は消えない）
2. 直近28営業日の利益 ≤ 0 **かつ** `G.cash < yBillLines().total` … 赤字続きで、次の支払いに届かない
3. ヤミ金の残債あり **かつ** 直近28営業日の利益 ≤ 0 … 借りたまま、返す当てがない

⚠ **借金の「額」で分けてはいけない**（2026-08-09 通しプレイで作り替え）。
旧版は `純借金（残債−現金）≥1,000万` を廃業の条件にしていたが、ビルの借入5,000万
（`CONF.startDebt`）は**7年返済**で120日ではほとんど減らない＝**誰も条件から抜けられない**。
実測：現金1,583万・通期利益558万・直近28日も黒字・客134人／日・6位で完走した店が「廃業」になった。
あれは経営に失敗した店ではなく、**優勝しなかっただけの店**だった。
いまは「額」ではなく「**払えているか**」で分ける＝借金が残っていても、返せているなら店は続く。

- 採点側 debtNow（battle_y.js:484 付近）にも `(G.yami.debt||0)` を**加算して対称化**する
  （壁打ち3回目：非対称のままだとサラ金を借りるほど hyoka が減り debtPt が上がる逆転が55点境界で起きる。
  影響は最大+0.3点程度でバランスは実質据え置き）
- 総合点 = `yBattleScore100().total`。ただし**傘下の55点判定は `b.scoreSnap`（下記§5）を使う**
- 判定表（12ケース・実測で全問一致 2026-08-09）：通しプレイの実データ→人気店／落とした→廃業／
  赤字＋手元薄→廃業／ヤミ金＋赤字→廃業／借り増し＋高得点→傘下／借り増し＋低得点→人気店／
  借金を減らした→人気店／無借金→人気店／優勝＋絆→真／優勝のみ→優勝／黒字で手元薄→人気店／
  赤字だが手元厚い→人気店
- rank≤2・常連≥150 は**条件から撤去**（台詞の飾り分岐にのみ使ってよい）

**絆の算出**（隠しパラメータ・バーは出さない＝SAUNA_BATTLE.md）：
`デート合計 ≥ 2` **または** `w.stoppedEver ≥ w.pushedEver`。

（壁打ち2回目で生カウンタ化→**3回目で日単位ネットに再改訂**）既存の `w.stopped / w.pushed` は
**判定に使わない**（pushedはデートで減り水明ギフトで0リセットされる機嫌変数＝¥27,000で絆が買える）。
回数カウンタも使わない（「やめておく→買い直して押し切る」の対で全購入を(1,1)にできる＝知識チェックに堕ちる）。
ED判定は**日単位ネット**で数える：
- `w.stoppedDays`＝equip/zou（実物の買い物）の関門で「やめておく」を選び、**その日押し切りが一度も無かった日**の数
- `w.pushedDays`＝equip/zou の関門を押し切った日の数（回数でなく日数・kouko/fee/sarakinは両側とも数えない）
- 絆＝ `デート合計 ≥ 2` または `stoppedDays ≥ pushedDays`
- 「やめておく」を選んだら `w.nagDay` をリセットする（**equip/zou のdeclineのみ**。fee/koukoまで
  リセットするとモーダルスパム経路になる）。現行は関門表示時点で nagDay が立つため
  「1個目でやめておく→残りを無関門で買い漁る」洗浄が成立している＝実装時に塞ぐ
- 両カウンタ0＝関門が一度も出なかった健全経営は**絆あり**（一貫した設計として意図）
- デート合計 = `Object.values(G.ch2.dateBeen||{}).reduce((a,x)=>a+x,0)`（訪問種類数ではない・壁打ち1回目）
- 妻の機嫌は現行 `gauges:false` で凍結中のため**条件に使わない**。gauges:true 運用時のみ「機嫌≥70」を追加要件にしてよい
- 合格基準：①月曜運最悪（デート0回）でも行動で成立する ②押し切り累計10・思いとどまり0のプレイが
  最終日の水明ギフト1回で絆成立**しない** ③同日「やめておく→同一物を買い直して押し切り」の日は
  (stoppedDays, pushedDays)=(0,1) と数えられる ④kouko3回＋値上げ2回だけの120日で pushedDays=0

## 5. 数値の抜け道チェック

- 絆は**軽くてよい**（エンディング分岐は攻略でなくご褒美）。ただし運だけで落ちないこと＝
  「月曜抽選が最悪（デート0回）でも `w.stoppedEver` で成立する」が合格基準（壁打ち1・2回目）
- 真の「通期黒字」`b.profitSum > 0` は資本支出を含まず**+1円でも成立する激甘条件だが意図**
  （絆とwinが実質ゲート。黒字条件は「商いとして立っていた」の記号でよい）
- **予告とスコアスナップ**（壁打ち3回目で全面改訂）：
  - 現行の予告news（`G.day === bday-1`）は**一度も発火しない**（119日目=月曜定休・日報が無い）。
    発火条件を「開催日前の**最後の営業日**に一度だけ」（`G.day >= bday-2 && G.day < bday && !b.notice`）
    に変える＝実質118日（日曜）夜
  - 予告発火時に `b.scoreSnap = yBattleScore100().total` を保存し、
    **廃業／傘下の55点判定はスナップ値で行う**＝「予告に出た点で審査される」がプレイヤーへの約束になる。
    スナップ後の駆け込み散財・最終日の赤字はED種別に影響しない（安全線問題そのものが消える）
  - 合格基準テスト：①通しプレイで予告newsが正確に1回出る ②予告時60.0点の盤面が
    120日にどれだけ散財・赤字でも傘下判定で55を割らない
- kouko借入は ED判定では「借り増した」側に効く（傘下の条件）。サラ金は廃業条件3とヤミ金加算の両方で効くため徳政令にならない（§1）
